建档 #

谁触发：你输入的第一句普通的话。斜杠命令不触发。

这句话先进入内存里的对话，然后才看有没有文件。session.ts 里的 writer 为空，说明还没有——刚启动，或者刚执行过 /clear。这时 createSession 才动手：建目录、独占创建文件、写上锁、写第一行封面。所以只打一个 /help 就退出，磁盘上不会留下任何东西。

文件名取这句话的第一行：去掉控制字符和头尾的点，不能进文件名的符号收成横线，最长 40 个字，后面加下划线和 4 位十六进制。撞上了就重抽，最多 8 次。

这份文件长什么样

它不是一份完整的 JSON，而是一行一条记录，永远只往末尾加，不回头改。一句对话对应一行，所以追加一句只是多写一行；读的时候一行一行解析，某一行坏了只丢这一行，其余照常读出来。

3message模型回复，里面可能带一次工具调用
4message那次调用的结果，例如 read 读到的内容

每行开头的 type 决定这行是什么。对话行里的 role 分出是你说的、模型回的、还是工具结果。第三行的 call_1 和第四行的 toolCallId 是同一个值，这就是前面说的配对；usage 是这一轮的 token，/cost 和底栏的数字由这些值累加而来。

封面只有第一行有，而且只写一次。它是这份会话的身份信息：当时在哪个目录、用的哪个厂家和模型、显示名是什么。列表里显示的名字来自这里，/rename 改的也是这里。它不参与对话——下次打开这份会话，用的仍是你启动时的厂家，不会按封面里记的那个切回去。版本号现在是 1；如果哪天读到一份版本号更大的，说明它是更新的 ti 写的，整份拒绝打开，而不是按老规则去猜。

中间每一行都是一句对话。你说的话、模型的回复、工具返回的结果，在内存里是同一种东西，落盘也就是同一种行，没有分表。模型回复那一行里可能带着一次工具调用，紧跟其后的那行就是这次调用的结果，两者靠调用编号对上。这个配对关系在恢复时很关键：只有调用、没有结果，下一轮请求会被接口拒掉，所以读入时会把缺的那份补上。

最后那种分隔现在写不出来。它是给以后的上下文压缩留的位置：压缩之后在这里划一道，读取时只取这道线之后的内容，线之前的原文仍留在文件里当记录。这一版没有任何命令会写它，但读取逻辑已经按「只取最后一道线之后」来实现，所以将来加上压缩，跨进程也能生效。

此外每份会话旁边还有一个同名的锁文件，内容就是正在写它的进程号。它不是对话内容，只用来挡住第二个 ti，规则见最后一节。目录权限 0700，会话文件 0600。当前目录是 git 仓库、并且 .gitignore 里还没有 .ti 时，建档会补上一行 .ti/，免得对话被提交上去；只打开旧会话不会去动它。

追加 #

谁触发：你的每一句，以及 agentTurn 里的模型回复、工具结果、中断说明。都走 pushMessage。

落盘在 appendLine：打开文件，写一行，刷到磁盘。打开方式必须既能读最后一个字节、又能往末尾写——只写打开的话，读那个字节会失败，封面之后的每一句都存不进去。

末尾没换行意味着什么

上一次写到一半就断了。补换行之后，那半截单独占一行；以后读取时它解析不出来，直接跳过，不会连累下一句。

撤回 #

谁触发：agentTurn 抛错，并且此时一个字的回复都还没写出。

判断条件是消息条数仍等于刚写下你那句之后的条数。满足才调 popMessage。已经写出的回复和工具结果一律留着，不往回删。

内存先去掉最后一句。文件那边从末尾按字节找最后一行——先看最后 1 MB，这段里没有换行就把窗口翻倍，直到看见换行或到文件开头。按字节而不是按字符，是为了不把一个汉字从中间切开。

取决于末尾那一行是什么
最后一行文件结果
完整的一句从这行第一个字节截断两边都少这一句
半截，解析不了只去掉这截垃圾上一行完好
封面或压缩分隔一个字节不动对话少一句，文件还留着

正常的失败路径里，最后一行就是你刚说的那句，所以文件回到只剩封面。截断本身出错，同样记进本轮的提示。

恢复 #

谁触发：命令行 --resume（main.ts 在厂家定好之后调用），或对话中的 /resume。两条都进 pickAndResume。

列出当前目录最多 10 份，按修改时间新的在前。一份都没有、你取消了、或者这个终端不能交互，都保持现状：不换档，也不退出，不能交互时只把列表印出来。选中的正好是正在写的那份，提示 already on this session。

接着检查能不能打开：路径必须落在当前的 sessions 目录里（按真实路径判断，符号链接指向外面的不行），封面版本号大于 1 则整份拒绝。都通过才读入，并且先锁新文件、再放开旧文件——锁不上的话，内存里的对话不换，旧文件的锁还在手里。

读进来时逐行的处理
读到的行放进这次对话
坏 JSON，或形状不对跳过
你说的一句先补上还没结束的工具结果，再放入
工具结果，对得上调用放入，并消掉这次调用
工具结果，对不上丢掉
读完仍有未结束的调用补一条错误结果

修补只发生在内存。补出来的那句是 Error: missing tool result (session repaired)，不回写文件，所以下次打开会按同样规则再补一次。最后历史直接灌进数组、画回屏幕，提示 resumed N messages。单条超过 4000 字只在屏幕上截断，文件里的原文不动。

为什么不走 pushMessage

那是「新增一句」的入口，会往文件末尾追加。恢复时如果用它灌历史，文件末尾就会多出一整份副本。

改名与互斥 #

谁触发：/rename 新名字；/clear；以及第二个 ti 打开同一份。

改名时显示名取第一行，文件短名按建档那套规则重做，原来的 4 位后缀尽量保留。新名字用硬链接先占住，锁上之后再删掉旧名字——直接改名会覆盖磁盘上已经存在的另一份会话，所以不能用。不带名字的 /rename 只显示当前名字，还没有文件时说 no session yet。

五种情形
情形文件屏幕
新名字没人占换成新名字renamed
新名字已有一份另抽后缀，最多 8 次那一份完好
不能做硬链接旧名字不动session not saved
第二个 ti 来开打不开session is in use
你执行 /clear旧文件留着下一句另建一份

锁的规则在 acquireLock：锁里的进程号就是自己，视为已经拿着；进程还活着、或者没有权限探测它是否活着，都拒绝；进程确实不在了，删掉锁再试，最多 5 次。这个 ti 退出时放开自己那把锁。/clear 走 endSession，只是放开锁、忘掉 writer，不删文件。
